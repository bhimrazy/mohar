### Changed

- **`deploy:check-migrations` enforces the lock rules and catches what it missed (#157, #307, #317, #389).** A pending migration now also fails the pre-deploy check when it runs DDL on an existing table outside `LockTimeout::run`, builds an index outside `OnlineIndex` (or uses `OnlineIndex` without `$withinTransaction = false`), reuses another migration's timestamp, or hides a drop in a helper method, `Schema::connection()` or raw `ALTER COLUMN … TYPE` / `SET NOT NULL`. A foreign key dropped and added again stricter, and a unique index or constraint on an existing table, need a `@compatible` or `@contract` tag. A tag now needs a reason and excuses one statement only. Migrations merged before this release that break the new rules are skipped. Upgrade note: a custom migration that trips a rule can be fixed, or the check skipped once with `DEPLOY_SKIP_MIGRATION_CHECK=1` after review.
