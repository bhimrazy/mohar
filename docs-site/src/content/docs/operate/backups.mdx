Back up three things and keep them apart from each other:

1. **The database**: at least daily, and before every upgrade.
2. **The object storage bucket**: invoice PDFs, ticket attachments, exports and brand files live only there.
3. **The application key** (`APP_KEY`, in your `.env` file): store it in a password manager or secrets store.

<Aside caution>
	Keep the key away from the database dumps. Without the key, the gateway, registrar and server credentials in a
	dump cannot be decrypted. With both together, whoever reads them has all of those credentials.
</Aside>

Copy backups off the server, to another provider or region. Schedule the database dump before the 03:00 daily
automation run.

<Tabs syncKey="install">
<TabItem label="Docker Compose">

**Database**, from the host's cron:

```bash
docker compose -f /srv/billing/deploy/compose.prod.yaml exec -T postgres \
  sh -c 'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" --format=custom' > /backups/billing-$(date +%F).dump
```

**Objects:** copy the `mohar_rustfs-data` volume, or point the `OBJECTS_` settings at a managed bucket with
versioning or replication turned on.

**Restore** into an empty stack (a new host, or after removing the volumes):

<Steps>

1. Start the database and object storage.

    ```bash
    docker compose -f deploy/compose.prod.yaml up -d --wait postgres rustfs
    ```

2. Load the dump.

    ```bash
    docker compose -f deploy/compose.prod.yaml exec -T postgres \
      sh -c 'pg_restore -U "$POSTGRES_USER" -d "$POSTGRES_DB" --no-owner --exit-on-error' < /backups/billing-2026-10-19.dump
    ```

3. Put the objects back into the `mohar_rustfs-data` volume, then start everything with the same `APP_KEY` as the
   backup.

    ```bash
    docker compose -f deploy/compose.prod.yaml up -d --wait
    ```

</Steps>

</TabItem>
<TabItem label="Without Docker">

**Database**, from cron (give `pg_dump` its password through `~/.pgpass`, mode 600):

```bash
pg_dump --format=custom --no-owner --file=/var/backups/billing/billing-$(date +%F).dump \
  "postgresql://billing@127.0.0.1:5432/billing"
find /var/backups/billing -name 'billing-*.dump' -mtime +30 -delete
```

**Objects:** turn on bucket versioning or replication, or copy the bucket to another provider on a schedule (for
example with `rclone sync`).

**Restore test:** restore the latest dump into a scratch database, point a copy of the app at it with the same
`APP_KEY`, and run the installer's checks:

```bash
createdb billing_restore && pg_restore --no-owner --dbname=billing_restore <file>
php artisan app:install --no-interaction
```

Every reference row should report as unchanged.

</TabItem>
</Tabs>

## Test a restore

Restore into a scratch database before you go live, and then every quarter. After the restore, sign in and open an
invoice PDF: that checks the bucket as well as the database.
