# WHMCS parity study, slice A: admin and client functional surface

Date: 2026-10-18. Status: complete for slice A.

Summary: 664 items across sections 1 to 20. Built 327, Partial 42, Specified 83, In progress 15, Missing 181,
Not needed 16. By priority: P0 287 (Built 241, Partial 10, Specified 20, In progress 7, Missing 9), P1 212
(Built 80, Partial 23, Specified 43, In progress 7, Missing 59), P2 165 (Built 6, Partial 9, Specified 20,
In progress 1, Missing 113, Not needed 16). Page inventory (section 21): 246 WHMCS pages, 134 matched, 10 not needed,
102 missing (12 P0, 49 P1, 41 P2). Source coverage (appendix A): 1,415 doc URLs, 550 in this slice.
The P0 Missing items and their proposed fixes are in section 22.

Scope: what WHMCS admins and clients can see and configure. Developer architecture (API, hooks, module
contracts, cron internals, templates) and release notes / community pain points are covered by the other two
slices. Sources: docs.whmcs.com (WHMCS 9.0 docs, page list from `https://docs.whmcs.com/9-0/sitemap.xml`, plus the
three pages that exist only in 9.1), read 2026-10-18, by four researchers (General Settings and Automation; the
Configuration area; admin operations, reports, utilities and logs; client area, cart and auth pages). The public demo
was not reachable (`demo.whmcs.com` did not resolve; `www.whmcs.com/demo/` returned 404), so nothing was taken from it.
No protected source was read. All descriptions are in our own words. Known limits of the source: WHMCS does not publish
its full admin-role permission list or the full client-user permission list, and escalation rules are only briefly
documented; section 8 compares by category for that reason.

How to read the tables:

- Status. **Built**: in code on `develop` (file or setting key cited). **Specified**: in a spec under
  `docs/product/` (file and section cited) but not built. **In progress**: an active workstream (Notifications,
  Nepal payments, Dashboard v2, Currencies). **Partial**: part of the WHMCS behaviour exists (cited); the rest is
  missing. **Missing**: no code; "Missing (out of scope, spec §)" means a spec explicitly leaves it out of v1.
  **Not needed / Not relevant / Not planned**: exists in WHMCS only because of its self-hosted design, or we decided
  against it (reason given).
- A setting key such as `orders.require_tos` is registered in `app/Modules/<Module>/<Module>ServiceProvider.php`
  through `SettingsRegistry` and edited on `/admin/settings/{section}` (`resources/js/pages/admin/platform/settings/edit.tsx`).
- Priority. **P0**: a host cannot switch from WHMCS without it (v1 parity). **P1**: expected soon after. **P2**: nice to
  have or niche.
- "Better" is filled only where we have a concrete improvement over the category.
- Mohar status checked against `develop` at `b7c30d8` on 2026-10-18 (routes from `app/Modules/*/routes/*.php`, pages
  from `resources/js/pages`).

## 22. Top gaps

### 22.1 P0 items that are Missing (no code, no spec), by owning module

**Services (provisioning)**

- cPanel/WHM driver (§6.2). Spec and build a `cpanel` driver on `ProvisioningDriver` (create, suspend, unsuspend,
  terminate, change package, password, usage, SSO via a WHM user session); most switching hosts run cPanel.
- DirectAdmin driver (§6.2). Same contract, second driver; common with Nepal and India budget hosts.
- Import existing server accounts (§6.1). Add `listAccounts` to the driver contract and an admin "import accounts"
  screen that matches accounts to clients and products, so a host can onboard customers who are not in WHMCS.
- Control-panel SSO from the client area (§18). Expose the optional SSO capability as a "Log in to control panel"
  button on `client/services/show.tsx` once a panel driver exists.

**Support**

- Mailbox import over IMAP/POP3 with Google and Microsoft OAuth (§7). Add an IMAP `InboundDriver` polled per department
  by the scheduler, reusing `ProcessInboundEmail`; hosts on shared mail cannot set up a piping webhook.

**Notifications (mail transport)**

- Mail provider admin UI (§1.5, §11). A `mail` settings section (SMTP, Mailgun, SES, Postmark, SendGrid; OAuth for
  Google/Microsoft later) applied to the Laravel mailer at runtime, secrets write-only.
- Test mail configuration (§1.5). "Send test" before save; keep the old config when the test fails.

**Core / Platform (client users)**

- Staff-triggered password reset for a client user (§12). "Send reset link" on the client Logins card; never let staff
  set or see a password.
- Client-side user management (§18, page inventory "User management"). `client/account/users` pages for the owner to
  invite, set per-account permissions and remove users, reusing the Core invitation and permission model.

### 22.2 P0 items that are Specified, In progress or Partial and still block a switch

Not Missing, so outside 22.1, but a host moving from WHMCS needs them in v1:

- Email templates, merge fields, email log, client Emails tab, manual send (Notifications, in progress).
- Reports library and CSV exports: aging, tax liability, income, new clients, renewal-reminder log (Reports, specified).
- Captcha on signup, checkout, login and tickets (Platform, specified in platform-admin §7).
- Credit and debit notes as the only way to change an issued invoice (Billing, partial).
- Card and UPI gateways outside Nepal: Stripe, Razorpay (Billing, specified later in payments-nepal §6).
- ResellerClub registrar and the `.np` manual flow (Registrars, specified).
- WHMCS importer (Migration, specified).
- Client profile tabs inline instead of quick links to filtered lists (Platform, partial).
