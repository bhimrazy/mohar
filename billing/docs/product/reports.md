# Reports & Dashboard — Product Spec (v1)

Status: draft for engineering · Owner: Reports workstream · Refines FEATURE_MAP §9
Clean-room: behaviour derived from public category docs (WHMCS, Blesta, FOSSBilling); naming/schemas are ours.

## 1. Purpose & scope

Admin dashboard (badges + widgets) and a fixed v1 report library with exact, testable metric definitions and CSV export.
Reports are read-only over other modules' tables, plus Reports-owned snapshot tables (MRR, movements). No custom report builder.

## 2. Global conventions (apply to every metric) — MUST

- **Time zone & periods:** period boundaries are calendar periods in `system.timezone`; "today" = local date. Stored timestamps are UTC and converted before bucketing.
- **Base currency:** multi-currency sums are converted to the default currency. Cash metrics use the rate snapshot on each row
  (`transactions.exchange_rate_to_default`, see billing.md); forward-looking metrics (MRR, forecast, outstanding) use the **current** rate.
  Every report also offers `currency=XXX` to show only native rows without conversion.
- **Money:** integer minor units; conversion rounds half-up per row, then sums.
- **Exclusions:** orders/services in status `fraud` are excluded everywhere; transactions of deleted clients still count (cash happened).
- **Tax:** income metrics are gross of tax unless named `_ex_tax`; MRR and forecast exclude tax.

## 3. Entities (Reports-owned)

- `report_mrr_daily (date, product_id, currency, kind: service|addon|domain, active_count, at_risk_count, mrr_native, mrr_base, at_risk_mrr_base)` — unique `(date, product_id, currency, kind)`. **MUST**
- `report_mrr_movements (id, occurred_on, subject_type: service|addon|domain, subject_id, client_id, product_id, movement: new|expansion|contraction|churn|reactivation, delta_mrr_base, source_event_id unique, created_at)`. **SHOULD**
- `report_exports (id, staff_id, report_key, filters json, status: queued|ready|failed, path, row_count, expires_at)`. **SHOULD**
- `dashboard_preferences (staff_id, layout json: [{widget, visible, position}])`. **SHOULD**

## 4. Metric definitions

| Metric                                 | Definition                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Gross cash in** (period)             | Σ `amount_in` of transactions with `type ∈ {payment, manual_income}`, `status = succeeded`, `occurred_at` in period. Credit applied to invoices is **not** cash (it was counted when deposited via an add-funds payment).                                                                                                                                                                                                                                                                                                                                    |
| **Refunds**                            | Σ `amount_out` where `type = refund`, counted in the refund's period (not the original payment's).                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| **Chargebacks**                        | Σ `amount_out` of `type = chargeback` − Σ `amount_in` of `type = chargeback_reversal`, in period.                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| **Fees**                               | Σ `fee` of succeeded transactions in period.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| **Income** (dashboard)                 | Gross cash in − Refunds − Chargebacks.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| **Net income**                         | Income − Fees − Σ `amount_out` of `manual_expense` (e.g. affiliate manual payouts).                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| **Income by gateway**                  | Income grouped by `transactions.gateway`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| **Revenue by product (invoice basis)** | Invoices with `paid_at` in period: Σ line `amount_ex_tax` grouped by product (domains by TLD, addons by addon). Includes invoices paid with credit; excludes `add_funds` invoices. Labelled "invoice basis — differs from cash income".                                                                                                                                                                                                                                                                                                                      |
| **Outstanding** (now)                  | Σ balance due (`total − amount_paid − credit_applied`) of invoices in status `unpaid` or `payment_pending`.                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| **Overdue**                            | Outstanding restricted to `due_date < today`; count + amount.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| **Aging buckets**                      | Overdue by `today − due_date`: 1–30, 31–60, 61–90, 91+ days; plus "not yet due".                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| **Normalised monthly amount**          | `recurring_amount / months(cycle)`: monthly 1, quarterly 3, semiannually 6, annually 12, biennially 24, triennially 36; `one_time`/`free` → 0. Domains: `recurring_amount / (12 × period_years)`. Uses the recurring amount after recurring promotions, × (1 − client-group discount %).                                                                                                                                                                                                                                                                     |
| **MRR** (as of date D)                 | Σ normalised monthly amount of services and addons `active` on D, plus domains `active` with `auto_renew = true` when `reports.mrr_include_domains: true`. Suspended items excluded and reported as **At-risk MRR**. Converted at D's rate.                                                                                                                                                                                                                                                                                                                  |
| **ARR**                                | MRR × 12.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| **MRR movements** (month M)            | New = items first activated in M; Expansion / Contraction = positive / negative MRR delta from upgrades, downgrades, price changes in M; Churn = MRR (value just before the change) of items that became `cancelled` or `terminated` in M; Reactivation = items returning to `active` from `cancelled/terminated` in M. **Net new MRR** = New + Expansion + Reactivation − Contraction − Churn. Invariant: MRR(end M) − MRR(end M−1) = Net new MRR + FX effect (FX shown as its own line). Suspension/unsuspension moves between MRR and at-risk, not churn. |
| **Service churn rate** (period)        | Items that became cancelled/terminated in period (excluding items never activated) ÷ items active at period start.                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| **Revenue churn rate**                 | Churned MRR in period ÷ MRR at period start.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| **Client churn rate**                  | Clients with ≥1 active item at period start and 0 at period end ÷ clients with ≥1 active item at period start.                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| **New clients**                        | Clients created in period (excluding clients whose only orders are fraud). **New paying clients** = clients whose first succeeded payment falls in period.                                                                                                                                                                                                                                                                                                                                                                                                   |
| **ARPA**                               | MRR ÷ clients with ≥1 active item (same as-of date).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| **Orders**                             | Orders created in period by status; **Order conversion** = orders that reached `active` ÷ orders placed (cohort = placement period).                                                                                                                                                                                                                                                                                                                                                                                                                         |
| **Tickets opened**                     | Tickets created in period (excluding tickets merged into another), by department, source, priority.                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| **First response time**                | Per ticket `first_staff_reply_at − created_at` in minutes (staff `reply` messages only; no notes, no autoresponses). Median and p90 over tickets created in period with a staff reply; tickets created in period without a staff reply are counted as **Unanswered**.                                                                                                                                                                                                                                                                                        |
| **Resolution time**                    | `closed_at − created_at` for tickets closed in period (latest close); median and p90.                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| **Replies per ticket**                 | Staff replies ÷ tickets with ≥1 staff reply (tickets created in period).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| **Reopen rate**                        | Tickets closed in period that were reopened at least once ÷ tickets closed in period.                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| **Staff activity**                     | Per staff in period: distinct tickets replied, replies, notes, average reply rating.                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| **Reply rating**                       | Average and 1–5 distribution of client ratings on staff replies created in period.                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| **Awaiting reply (now)**               | Tickets whose status has `is_awaiting_reply`, in departments the viewer can access.                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |

- Median of an even-sized set = mean of the two middle values; p90 = nearest-rank. **MUST**

## 7. Exports

- CSV: UTF-8 (`reports.csv_bom: false`), comma separator, header row, ISO-8601 dates, money as decimal strings plus a currency column; cells beginning with `=`, `+`, `-`, `@`, tab or CR are prefixed with `'` (formula-injection guard). **MUST**
- Exports above `reports.sync_export_max_rows: 5000` rows are queued; the staff member gets a signed, owner-only download link valid 24 h. **SHOULD**
- Every export writes an activity log entry (`report.exported`, key, filters, row count). **MUST**
- Entity exports (clients, services, domains, invoices, transactions) with up to 5 field filters. **SHOULD**

## 8. Automation

- `reports:snapshot-mrr` daily 00:15 local — upsert `report_mrr_daily` for the previous day; idempotent; `reports:backfill-mrr --from --to` rebuilds from current data (marked approximate). **MUST**
- MRR movement recorder — queued listeners on `ServiceActivated`, `ServiceUpgraded`, `ServiceTerminated`, service cancellation processed, reactivation, `DomainRegistered`/`DomainTransferred`, `DomainExpired`, `DomainAutoRenewChanged`; idempotent by `source_event_id`. **SHOULD**
- `reports:prune-exports` daily. **SHOULD**

## 9. Events emitted

`ReportExported(reportKey, staffId, rowCount)`, `MrrSnapshotCompleted(date, mrrBase)`.

## 10. Edge cases & pitfalls

- Cash vs invoice basis disagree (credit-paid invoices, add-funds, refunds in later periods) — label clearly; never mix both in one figure.
- Double counting credit: the deposit is cash, applying credit is not.
- A refund of a prior-year payment reduces the current period.
- FX moves change MRR without customer action — FX effect shown separately.
- Annual plans make monthly cash spiky — use MRR for recurring trends.
- Suspended services excluded from MRR (at-risk line) to avoid overstating.
- Prorated/upgrade invoices are not MRR; only the new recurring amount is.
- Midnight/DST boundaries — convert to `system.timezone` before bucketing.
- Free services/domains count in active counts but contribute 0 MRR.
- Performance: index `transactions(occurred_at)`, `invoices(status, due_date)`, `tickets(created_at, department_id)`; paginate lists; cache dashboard.
- Permission leaks: ticket metrics only for accessible departments unless `support.tickets.access_all`.

## 11. Acceptance criteria

1. Given payments of 100.00 and 50.00 today and a 20.00 refund today, Then dashboard income today = 130.00.
2. Given a 100.00 payment last month refunded today, Then last month's income stays 100.00 and this month's includes −100.00.
3. Given a EUR payment of 10.00 with snapshot rate 0.90 EUR per USD (default USD), Then it contributes 11.11 USD.
4. Given 30.00 of credit applied to an invoice, Then gross cash in is unchanged.
5. Given an invoice total 100.00 with 40.00 paid, due yesterday, Then outstanding includes 60.00, overdue count = 1, bucket 1–30.
6. Given active services monthly 10.00, annual 120.00, quarterly 30.00 and a one-time 50.00, Then MRR = 30.00 and ARR = 360.00.
7. Given a suspended monthly 10.00 service, Then MRR excludes it and at-risk MRR = 10.00.
8. Given an active 2-year domain at 24.00 with auto-renew and `mrr_include_domains`, Then it adds 1.00 to MRR; with auto-renew off it adds 0.
9. Given a client group with 10 % discount and a 20.00 monthly service, Then its MRR contribution = 18.00.
10. Given 100 active services at period start and 5 cancelled/terminated in the period, Then service churn rate = 5 %.
11. Given a service cancelled while still pending, Then it is not counted as churn.
12. Given MRR movements for a month, Then ending MRR − starting MRR = net new MRR + FX effect, exactly in minor units.
13. Given first staff replies after 10, 20, 30 and 120 minutes and one unanswered ticket, Then median first response = 25 min and unanswered = 1.
14. Given a ticket whose only staff activity is a note, Then it is unanswered.
15. Given the MRR snapshot job runs twice for the same date, Then one row per key exists with identical values.
16. Given a client named `=HYPERLINK(...)`, When exported to CSV, Then the cell starts with `'=`.
17. Given staff without `reports.mrr.view`, Then the MRR widget is absent and the report endpoint returns 403.
18. Given staff limited to department A, Then `tickets_overview` counts only department A tickets.
19. Given a scheduler heartbeat older than 10 minutes, Then the automation widget shows a stale warning.
20. Given any export, Then an activity log entry with report key and row count exists.

## 12. Out of scope for v1

Custom report builder, scheduled/emailed reports, cohort/LTV analysis, BI/warehouse connectors, server revenue/profit reports, disk-usage reports,
VAT MOSS-style returns, PDF batch invoice export, map visualisations, predictive forecasting.
