## 2. Right things, right order, for a Nepali host?

Mostly yes. The four 10-22 pulls are done or nearly done. What is left on the switch path, in order:

- **Finish VAT before anything new in Billing.** The notes and register are built but a host cannot turn Nepal VAT
  mode on (#432, then VAT PRs 3b, 4, 5, 7). Every day this stays open the most valuable work of the week is invisible.
- **Pull forward: import unpaid invoices and domains.** This is now the biggest gap between "built" and "a host
  switches": day 3 of the first week is still re-typing. The registrar drivers make it worse, not better, until the
  importer records the order id (#338): today each imported domain is linked by hand (#365).
- **Pull forward: mail transport and a test send in admin** (roadmap 3.6). A host's first support ticket is "no
  email arrives"; today the answer is to edit `.env` on the server.
- **Defer: Namecheap enablement, more registrar fixes, more company-clock refactors.** ResellerClub covers the
  Nepali reseller market; Namecheap is a second gTLD driver few Nepali hosts resell. The clock work is correct but
  done; stop at #436.
- **Keep deferred:** WHMCS API connector until the CSV path imports invoices and domains; connectIPS until the owner
  starts enrolment; affiliates, AI, social sign-in, SMS, Nepali UI, medium and large load profiles.

## 3. Risks to the business

- **Tax rules unanswered, now blocking built code.** CBMS applicability, note numbering reset per fiscal year (D2),
  FX rate and zero-rated exports (D6) and assumptions A1 to A11 (`vat-register.md` §14) wait for an accountant,
  open since 10-19. The register and notes are built on assumptions; a wrong one means a re-filed return.
- **All external proof is self-made.** eSewa, Khalti, ResellerClub, Namecheap, WHM and the WHMCS API are each
  verified only against a simulator we wrote from public docs (decision 10-22). A misread doc is in both driver and
  simulator, so CI cannot catch it. The first real eSewa or Khalti payment will be a host's customer's.
- **Register correctness until #432's follow-up.** It counts any tax as VAT (a foreign sales tax included). Low impact
  for a Nepal-only host, wrong for one with US clients.
- **No release.** `main` is a landing page; no tag, no image a host can pull. FrankenPHP 1.13.2 waits for its
  cooldown (#406, 10-28); the first release run waits for the owner.
- **Sign-in under load.** On 2 vCPU, 28 simultaneous sign-ins take 1.3 to 1.8 s p50 (#433); the remedy (lower
  bcrypt cost) is a security trade-off for the owner. Admin dashboard is above its 200 ms target.
- **Data.** KYC citizenship scans encrypted, restore drill proved they decrypt only with the same `APP_KEY`: losing
  the key loses the documents. The repository is public, all rights reserved.
- **Capacity.** 108 open issues (+8 in two days), 14 tagged migration, 12 payments; the VAT stack is a long serial
  queue (3a, 3b, 4, 5, 7) on one Mac.

- **Day 2, company and money.** PAN, VAT 13%, lakh grouping, BS beside AD. Accountant asks for the sales book: the

  exists but cannot be switched on.
- **Day 3, clients.** CSV client import with review and undo works. Unpaid invoices and domains still re-typed;
  every `.com` from ResellerClub then needs "Link ResellerClub order" by hand, one domain at a time.
- **Day 4, payments.** eSewa and Khalti, including Continue payment; never tested against a live merchant. No
  connectIPS or card in NPR.
- **Day 5, domains.** `.np` guidance works; `.com` renewals and transfers through ResellerClub automate once linked.
- **Week end.** Client dashboard is in the calm direction with a pay banner; no reports beyond the two registers;
  English only; Devanagari names missing from register PDFs (kept in CSV).

What makes them leave, in order: a failed live wallet payment, re-entering invoices and linking domains by hand,
email not arriving, and no way to issue a credit note at month-end.
