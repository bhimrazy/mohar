### Added

- **Nepal VAT settings (Admin → Settings → Nepal VAT, #430).** Staff with `billing.tax.manage` and a recent password choose which tax rules are Nepal VAT, which 0% rule marks an export, and the BS month the mode starts in (the first day of the current or a later BS month). Each save is written to the activity log (`billing.nepal_vat.enabled` or `.changed`). Enabling turns on numbering when paid and the issue date on payment, sets the number increment to 1, and fixes the invoice and note numbering settings from then on. Enabling is refused while a numbered invoice has no tax snapshot or no VAT split, while the snapshot review list has unseen entries, while cached credited or debited totals differ from their adjustments, or when a cancellation, refund or late fee was written on a numbered invoice on or after the start day. Switching off is refused once a note exists. A tax rule the mode uses cannot be deleted.
- **Nepal VAT is recorded apart from other tax.** Invoices store the tax rules each level used (`tax1_rule_id`, `tax2_rule_id`, kept at 0% too). With the mode on, the snapshot stores whether each level is Nepal VAT (`fiscal_tax1_is_vat`, `fiscal_tax2_is_vat`) and sets `supply_class`: `export` only when the invoice used the export rule, `taxable` when a Nepal VAT level carries tax, otherwise `exempt`. A document with only other tax (for example India GST) is `exempt` for the register and keeps that tax in `fiscal_tax1`/`fiscal_tax2`. With the mode off nothing changes: `taxable` or `exempt` by the tax sum.
- `php artisan billing:fiscal-vat-split` classifies invoices numbered before this release (matching a level to a Nepal VAT rule by name and rate; none becomes an export). Run it after choosing the VAT rules; it is capped (`--max`, default 5,000), repeatable and not scheduled.

### Changed

- Upgrade notes: one migration adds four nullable columns and a partial index (`invoices_vat_split_pending_index`) to `invoices`, built concurrently on PostgreSQL. Nothing is backfilled by the migration. Before enabling the mode on an install with numbered invoices, run `billing:fiscal-snapshot` and `billing:fiscal-vat-split` until they report nothing left. Installs that never enable the mode see no change in invoices, numbering or reports.
