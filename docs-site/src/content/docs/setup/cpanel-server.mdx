Once a server is connected, paid orders create cPanel accounts on it, overdue services are suspended, and cancelled
ones are removed, following your [automation](../../daily/automation/) settings.

## Create an API token in WHM

Sign in to WHM as `root` (or as the reseller whose accounts you want to manage) and create an API token under
**Development → Manage API Tokens**. A token can be limited to the permissions the app needs. **Test connection**
reads the token's permissions and names any that are missing.

| Permission                                           | Used for                                         |
| ---------------------------------------------------- | ------------------------------------------------ |
| `basic-whm-functions`                                | checking the connection and WHM version          |
| `list-accts`, `acct-summary`                         | finding accounts, importing and usage            |
| `create-acct`                                        | creating accounts                                |
| `suspend-acct`                                       | suspending and unsuspending                      |
| `kill-acct`                                          | removing accounts                                |
| `upgrade-account`                                    | changing an account's package                    |
| `passwd`                                             | changing an account's password                   |
| `list-pkgs` (and `viewglobalpackages` for resellers) | listing packages                                 |
| `show-bandwidth`                                     | bandwidth usage                                  |
| `ns-config`                                          | reading the name servers (optional)              |
| `create-user-session`                                | single sign-on into cPanel (optional, see below) |

Copy the token when WHM shows it. WHM does not show it again.

## Add the server

<Steps>

1. Go to **Services → Servers** and select **New server**.

2. Under **Server**, enter a **Name** and the server's **Hostname**, for example `whm1.example.net`. Set **Maximum
   accounts** if you want a limit.

3. Under **Connection**, choose the driver **cPanel & WHM**. Leave **Port** blank to use 2087. Keep **Sign in with**
   on **API token (recommended)**, enter the WHM **Username** (`root` or the reseller) and paste the **API token**.
   Turn on **Default for this driver** if products without a server group should use this server.

4. Under **Nameservers and cost**, enter the name servers clients should use. They appear in the welcome email.

5. Save, then select **Test connection** at the top of the page.

</Steps>

## Read the connection check

The check signs in, reads the token's permissions, counts the packages you can assign and reads WHM's name servers.
Each line passes, warns or fails with a short reason.

<Screenshot name="test-connection" alt="A passing connection check: address and certificate, sign-in, permissions, account kind, packages and name servers." />

If the server uses a self-signed certificate, the check shows the certificate's details and offers **Trust this
certificate**. Compare the fingerprint with the one on the server before you trust it. After that, the app accepts
only that certificate for this server.

<Aside caution title="Single sign-on">
	**Single sign-on into cPanel and WHM**, under **Driver settings**, needs the `create-user-session` permission.
	Whoever holds a token with that permission can sign in as any account the token's owner owns. Leave it off if you
	do not need it.
</Aside>

## Use the server for a product

<Steps>

1. Open the product under **Setup → Products** and go to the **Provisioning** tab.

2. Choose **cPanel & WHM** as the **Provisioning driver**, then choose the **WHM package** the account should get. The
   list comes from the server.

3. Leave **Server group ID** empty to use the server marked **Default for this driver**, then select
   **Save provisioning**.

</Steps>
