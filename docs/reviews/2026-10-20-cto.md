## 5. Changes proposed

1. **GitHub merges, not watchers.** Owner flips two repo settings today: `allow_auto_merge` and
   `delete_branch_on_merge`, and adds a branch rule on `develop` requiring the `CI` check. `run-workstream` step 5
   becomes: sign-off comment → `gh pr ready <n>` → `gh pr merge <n> --auto --merge --match-head-commit <sha>`. No
   shell watcher, nothing to resume, drafts and UNKNOWN stop mattering. Expected: #100/#101-style idle time goes to
   zero; the 59 stale branches do not recur. Until the owner acts, a watcher may only be set on a PR that carries a
   CTO sign-off at its current head, and `resume-session` step 3 merges only such PRs.
2. **WIP pushes skip CI.** Operating model "Session restarts": WIP commits are `wip(<scope>): … [skip ci]`; the
   review-ready push is a normal commit. The `ci` label stays. Expected: runs per PR fall from 5–17 to 2–4, the
   queue disappears at current concurrency, cancelled runs (34 of 111) mostly vanish, billable minutes roughly halve.
3. **Replace the two-engineer rule with a budget that is checked.** Operating model "Waves" and "Machine limits":
   at most 4 agents running (2 writing code, 2 reviewing); no launch while the 1-min load is above 6; `state.md`
   "Running now" lists agent ids and the count. `resume-session` step 5 resumes in order (PRs awaiting sign-off,
   then fix rounds, then builds) within the budget, not all seven. Periodic reviews count against it: run them
   when load is under 6, or skip and note it, as on 10-19 14:20. Expected: reviews stop starting on moving heads,
   local test runs stop contending with CI diagnosis, fewer restarts if load is a factor (not established).
4. **Verification before any merge path.** Operating model "Gates by PR type": a PR whose latest review verdict is
   "Changes requested" cannot be marked ready; the CTO posts the sign-off only after a re-review or a recorded diff
   read naming each blocking item. `run-workstream` step 5 drops the local full-suite run (CI runs the same head) and
   keeps pint, phpstan, tsc, `vp check`, Vitest and the module's tests. Expected: no repeat of #101; 10–15 min of
   box time back per merge.
5. **Merge #91 first, then set the CI bar.** Board review today, merge, restore `timeout-minutes: 15` once three
   consecutive `develop` runs are under 8 min; decide the two items in #91 "Remaining" (seed once in
   `BillingSeederTest`; Unit/Arch on SQLite only) as a CTO decision this week. Expected: 5 min per run back for
   every PR, and the next 500 tests absorbed.
