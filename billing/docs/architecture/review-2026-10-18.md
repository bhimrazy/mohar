## 1. The system on `develop`

### What holds up

- **Boundaries.** `tests/Arch/ArchitectureTest.php` enforces the dependency rules. No module imports a sibling, the
  kernel imports no feature module, and no kernel DTO or event holds a model. Core null defaults (`bindIf` in
  `CoreServiceProvider.php:53-59`) keep modules working when siblings are absent.
- **The gateway SPI** (`app/Contracts/Billing`, #26) is the best extension contract in the codebase:
    - DTO-only inputs;
    - a per-call `GatewayConfig`, so drivers are stateless;
    - "only an authoritative lookup marks paid";
    - capability interfaces for optional behaviour.

    ADR 0009 uses it as the template.

- **Configuration vs settings.** `SandboxPolicy` keeps the "test money may exist" switch as a deployment config
  (`config/billing_sandbox.php`), not a staff setting. That is the right line between configuration and settings.
- **Money.** Integer minor units, `Money` with currency checks, and exact decimal rates without floats (`Decimal`, #43).

## 2. #43 Currencies — Changes requested

The kernel additions are well chosen:

- `CurrencyDirectory` is a service contract with a cached Core binding. It is invalidated by `Cache::forget` plus a
  generation counter, so memoised scoped copies refresh too.
- `ExchangeRateSource` and `PriceConverter` are small provider contracts, each used by more than one module.
- `RateSnapshot` keeps both sides of a rate fraction to avoid inversion error.
- `PriceRounding` is an enum with pure arithmetic.
- `EXCHANGE_RATES = 5` adds a stage without renumbering.

**Blocking**

1. **Converted prices have two write paths, and one is synchronous.**
    - Where: `Catalog/CatalogServiceProvider.php:63-69` and `Domains/DomainsServiceProvider.php:117-122` call
      `apply()` inside synchronous `ExchangeRatesUpdated` listeners. `apply()` rewrites every converted price in one
      transaction (`Catalog/Actions/ConvertPrices.php:63`).
    - Effects:
        - Staff saving a currency or approving a review (`Platform/Actions/Currencies/SaveCurrency.php:110`) wait on a
          catalogue-wide rewrite.
        - A Catalog exception turns into a failed Platform request.
        - The same run converts again in the SYNC stage (`catalog.convert-prices` at `CatalogServiceProvider.php:71`,
          `domains.convert-prices` at `DomainsServiceProvider.php:124`), and failures are attributed to the
          `EXCHANGE_RATES` task.
    - Fix:
        - Remove both listeners, so the event is purely an observation.
        - After commit, Platform dispatches one queued `ShouldBeUnique` job that runs every
          `PriceConverters::all()` entry whose `automatic()` is true, for manual, review and rebase changes.
        - The daily path stays the SYNC tasks.
2. **ADR drift.** Add an addendum to ADR 0002:
    - The server (`MoneyFormatter`) and the browser (`money.ts`) format through the currency's configured display.
    - `Money::format()` is for logs.
    - Display decimals are fixed at 2 (`Currency::DECIMALS = [2]`).

**Recommendations**

- R1. `ExchangeRateSources::register()` resolves every source at boot on every request (`ExchangeRateSources.php:27`),
  and `PriceConverters::get()` resolves all converters. Move to `register(key, class)` (ADR 0012); this can follow the
  merge as a compatible change.
- R2. Make `ExchangeRatesUpdated::$source` a backed enum (`App\Enums\RateChangeSource`). It gains
  `IdentifiesOccurrence` when #28 merges after it.
- R3. `MoneyFormatter::number()` truncates rather than rounds when `decimals <= 0` (`MoneyFormatter.php:89`). This is
  latent because only 2 is allowed. Either remove `CurrencyDisplay::$decimals` or round half up; `money.ts` likewise.
  The `decimals` shift in `Currency::convertTo()` is latent in the same way.
- R4. There are two implementations of one formatting rule set (PHP and TS). Drive both test suites from one
  golden-table fixture (`tests/Fixtures/money-format.json`).
- R5. Rate updates run on the UTC calendar, while NRB publishes on Nepal time. ADR 0013 covers this.

## 3. #41 Dashboard v2 — Approved (kernel changes)

`Dashboard` gains `breakdown`, `health()`, `variants`, `primary` and `mirrorsTodo`, plus `Trend` and Core's
`CurrencyRollup`. Every addition is compatible: trailing defaulted parameters and new optional payload keys. Widgets
read only their own tables, and cross-module data goes through `PriceBook` (ADR 0001). Skipping mirrored counters
without running their resolvers, together with the `DashboardQueryCountTest` ceilings, is the performance-budget
pattern we want everywhere.

**Recommendations**

- R1. `widget()` now has nine positional parameters (`Dashboard.php:61`). Freeze the positional list. Further options
  are named-only and are documented with named arguments (ADR 0010).
- R2. The payload shapes (`breakdown`, `variants`, `ranges`, `summary`) exist only in a docblock. Add one shape test
  per widget type, keep the TS types in one file, and adopt the rule that the renderer ignores unknown keys. That is
  what makes third-party widgets safe.
- R3. Keep the split that `mirrorsTodo` (registration: whether the resolver runs) and `primary` (payload: how it
  renders) imply, and write it in the docblock.
- R4. `CurrencyRollup::format()` goes through `Currency::format()`, which delegates to `MoneyFormatter` after #43, so
  nothing breaks. Call `MoneyFormatter` directly when rebasing.
- R5. `health()` becomes a read of the kernel `HealthChecks` registry when the watchdog lands (ADR 0014), as a pure
  move.
- R6. The calendar split noted in the PR (Orders in company time, the rest in UTC) is fixed by ADR 0013, not here.

## 4. #28 Notifications — Changes requested

The kernel additions are sound:

- `EmailTemplates` is the smallest interface that works, with a Core null default.
- The new `Brand` fields are trailing and defaulted.
- The webhook allow-list never exposes auth events.
- `PublishEventWebhooks` runs after commit.

**Blocking**

1. **Auth mail is an event used as a command, and the events carry secrets.**
    - Where:
        - `Models/User.php:135-160` chooses between Laravel's mail and Notifications with `Event::hasListeners()`.
        - `Events/Core/PasswordResetRequested.php:19-22` carries the reset URL and the raw broker token.
        - `EmailVerificationRequested` carries a signed URL.
    - Effects:
        - Every listener receives live credentials, including audit listeners, packages and future queued listeners.
          A queued listener would write them to `jobs` and `failed_jobs` in plain text.
        - An unrelated listener suppresses Laravel's fallback.
    - Fix:
        - Add a kernel contract `App\Contracts\Core\AuthMailer` with
          `sendPasswordReset(User $user, #[\SensitiveParameter] string $token)` and `sendEmailVerification(User $user)`.
          Core binds a default that sends Laravel's notifications. Notifications binds the templated mailer, which keeps
          its own fallback. `User` calls the contract.
        - If observation is wanted, keep the two events without the token or URLs.

    This preserves the CTO decision's intent (editable, logged, branded auth mail).

2. **Occurrence identity is not enforced.**
    - Where: `Notifications/Support/EventKey.php:24` duck-types with `method_exists()`, and nothing makes a new event
      use the trait (`ExchangeRatesUpdated` from #43 is the first that will miss it).
    - Fix:
        - Add `App\Contracts\Events\DomainEvent` (`occurrenceId()`), implemented by every event.
        - Add the arch rule
          `arch('events are identified')->expect('App\Events')->toImplement(DomainEvent::class)->toUseTrait(IdentifiesOccurrence::class)`.
        - `EventKey` types against the interface.

**Recommendations**

- R1. `$occurrenceId` is public and mutable. Make it `readonly` with lazy initialisation in class scope, use
  `Str::uuid7()`, and add `occurredAt` (ADR 0011).
- R2. Webhook payloads are merge-field resolver output (`Webhooks/WebhookPublisher.php:34`), so renaming a merge field
  breaks external integrations. Before the first external consumer:
    - add per-event webhook resources;
    - add `api_version` to the envelope;
    - replace the closed `WebhookEventTypes::MAP` with a registration method (ADR 0010, 0011).
- R3. The dark email logo is a `Brand` field, while the light one is `BrandProvider::emailLogoUrl()`. That is two ways
  to get the same thing. Add `Brand::$emailLogo` and deprecate the method.
- R4. `ShouldHandleEventsAfterCommit` on `PublishEventWebhooks` is correct, but it is the fourth after-commit
  mechanism. ADR 0011 converges on `ShouldDispatchAfterCommit` on events.
- R5. The new `notifications` and `webhooks` queues get workers only through `DevCommands`. Production topology is in
  ADR 0014.
- R6. The global `MessageSending` listener (`BrandOutgoingMail`) is acceptable. Document in `architecture.md` that,
  when Notifications is installed, it rebrands only the framework default sender on all outgoing mail, including
  packages' mail.

## 5. Payments kernel (#26, merged) — Accepted, with follow-ups

- `ConnectionTester`, `ProvidesLogo` and `SandboxPolicy` are correct uses of capability interfaces and deployment
  config. `PaymentAttemptRef::$interactive` and `RedirectInstruction`/`FormPost::$expiresAt` follow ADR 0008:
  trailing defaulted fields, no driver broken.
- F1. Deprecate the five dead gateway flags, and add the flag/interface consistency test (ADR 0012).
- F2. `ConnectionCheck`, `ProvidesLogo` and `GatewayLogo` apply to every integration. Move them to the `Integrations`
  area in ADR 0009 PR A.
- F3. Kernel `GatewayDriverRegistry`, so that packages stop needing `callAfterResolving()` (ADR 0012).
- F4. Pick one casing for kernel `toArray()` output and Inertia props. `GatewayLogo` uses
  snake_case (`dark_url`), `Brand` uses camelCase (`logoLight`). Recommend snake_case, matching API Resources. If more call-context flags like
  `$interactive` appear, add a `CallContext` argument through a new capability method instead of growing data DTOs.
