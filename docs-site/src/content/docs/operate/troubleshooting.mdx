## Install messages

| Message from `app:install`                                 | What to do                                                                                     |
| ---------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| `APP_KEY is not set`                                       | without Docker: `php artisan key:generate`, then `php artisan optimize`. With Docker: step 4 of the install |
| `Database: Cannot connect`                                 | check the `DB_` values, that PostgreSQL is running, and that the user can connect               |
| `Migrations: ... pending`                                  | run `php artisan migrate --force`                                                              |
| `Object storage: ... not writable`                         | run `php artisan objects:ensure-bucket`, then check the `OBJECTS_` values and the bucket policy |
| `... already exist, so none was created`                   | expected when you run it again; add `--additional-admin` to create another administrator      |

Warnings about mail, the queue or the scheduler do not stop the install. They clear once mail is set up and the
scheduler has run for a minute.

## Docker Compose

| Symptom                                       | Where to look                                                                                                      |
| --------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `up` stops at `migrate`                       | `docker compose -f deploy/compose.prod.yaml logs migrate`. "No full administrator was created" means the install step was skipped |
| 502 error from the site                       | `docker compose -f deploy/compose.prod.yaml ps`: `app` must be `healthy`. `logs app` says why it is not             |
| Certificate errors                            | DNS for your domain must point at the host, and ports 80 and 443 must be open. Check `logs caddy`                  |
| Activity log shows one IP address for everyone | the app does not trust the proxy: `EDGE_SUBNET` in `deploy/.env` must match the edge network's range              |
| Jobs are not processed                        | `logs worker-default`, or the worker for that queue. **Run now** in Automation uses `worker-automation`            |

## Any install

| Symptom                                           | Cause and fix                                                                                                      |
| ------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| Automation says the scheduler has never run       | the cron entry is missing or runs as another user (without Docker), or the `scheduler` service is stopped (Docker) |
| Emails are not sent                               | check the `MAIL_` settings and **Setup → Email log**; a queue worker must be running                               |
| Links in emails point to the wrong address        | `APP_URL` is wrong. Fix it, then run `php artisan optimize` (or recreate the containers)                           |
| A payment shows as pending                        | the app checks pending payments with the gateway every few minutes. See **Billing → Payment attempts** and **Setup → Gateway log** |
| A cPanel account was not created                  | open **Services → Module log** for the error. Fix the cause, then select **Retry** on the failed action                                    |
| A change to `.env` has no effect                  | the configuration is cached: run `php artisan optimize` (or recreate the containers)                               |
