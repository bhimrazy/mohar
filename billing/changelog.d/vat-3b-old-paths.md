### Changed

- **Cancelling, cancelling lines and late fees on a numbered tax invoice issue notes while Nepal VAT mode is on** (the mode itself stays hidden behind its feature flag until VAT PR 4). Staff cancel, auto-cancel and the modules that cancel an invoice (Orders, Services, Domains) issue one `invoice_cancelled` credit note for the open balance; cancel lines issues one `lines_cancelled` credit note, or the single cancel note when it cancels the last open line; a late fee is a debit note. Staff give a reason, which is printed on the note (the cancel and cancel-lines dialogs ask for it when the mode is on); a module's note reads "Cancelled by <module>". Reopen is refused for a numbered tax invoice, and a discount line is cancelled with the line it discounts. Proforma invoices, add-funds invoices and any path before the mode's start day behave as before; a note cannot be issued before the start day.
- Every old path now dates all the rows it writes with one instant taken after its invoice lock, and reads the mode under a shared lock, so enabling the mode waits for transactions in flight and none can write an old-style row dated on or after the start day.
- Enabling the mode is also refused while a refund recorded the old way (pending, with no note reservation) is open on a numbered invoice.
- Upgrade notes: `Invoicer::cancel` takes an optional reason (`?string $reason = null`); implementers of the contract must add the parameter. No schema change.
