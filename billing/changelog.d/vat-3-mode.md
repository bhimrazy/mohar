### Added

- **Nepal VAT settings (Admin → Setup → Nepal VAT, #430).** Staff with `billing.tax.manage` and a recent password choose which tax rules are Nepal VAT, which one 0% rule marks an export (nothing is pre-selected), and the BS month the mode starts in (the first day of the current or a later BS month). Each save is written to the activity log (`billing.nepal_vat.enabled` or `.changed`). Enabling turns on numbering when paid and the issue date on payment, sets the number increment to 1, and fixes the invoice and note numbering settings from then on; the Billing settings form shows them disabled with the reason, and a save that changes one is refused. Enabling, and moving the start day before it starts, are refused while a numbered invoice has no tax snapshot or no VAT split, while the snapshot review list has unseen entries, while cached credited or debited totals differ from their adjustments, or when a cancellation, refund or late fee was written on a numbered invoice on or after the start day. Switching off is refused once a note exists. A tax rule the mode uses cannot be deleted or have its rate changed.
- **Nepal VAT is recorded apart from other tax.** Invoices store the tax rules each level used (`tax1_rule_id`, `tax2_rule_id`, kept at 0% too). With the mode on, the snapshot stores whether each level is Nepal VAT (`fiscal_tax1_is_vat`, `fiscal_tax2_is_vat`) and sets `supply_class`: `export` only when the invoice used the export rule, `taxable` when a Nepal VAT level carries tax, otherwise `exempt`. A document with only other tax (for example India GST) is `exempt` for the register and keeps that tax in `fiscal_tax1`/`fiscal_tax2`. With the mode off nothing changes: `taxable` or `exempt` by the tax sum.
- `php artisan billing:fiscal-vat-split` classifies invoices numbered while the mode was off, by their stored tax rules (name and rate only where an invoice has none). It writes only invoices not yet classified, is capped (`--max`, default 5,000), repeatable and not scheduled; `--dry-run` lists the taxed levels it would class as other tax and writes nothing. Run it after choosing the VAT rules.

### Changed

- Upgrade notes: the Nepal VAT page and its routes are hidden (404, no menu item) until `FEATURE_BILLING_NEPAL_VAT_MODE=true`, and stay off by default until VAT PR 4 merges. Turning the flag off after enabling the mode only hides the page; the mode stays in effect. One migration adds four nullable columns and a partial index (`invoices_vat_split_pending_index`) to `invoices`, built concurrently on PostgreSQL; nothing is backfilled by it. Before enabling the mode on an install with numbered invoices, run `billing:fiscal-snapshot` and `billing:fiscal-vat-split` until they report nothing left. Installs that never enable the mode see no change in invoices, numbering or reports.
